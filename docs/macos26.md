# macOS 26 메뉴바 — 실측으로 확인한 사실과 함정

전부 macOS 26(Tahoe)에서 직접 측정한 결과입니다. 문서에 없는 비공개 동작이 많아서, 코드를
바꾸기 전에 여기와 충돌하지 않는지 확인하세요. "왜 이렇게 복잡하게 했지?" 싶은 코드는 대부분
여기 있는 이유 때문입니다.

## 상태 아이템 창

- 모든 상태 아이템 창의 소유자는 **Control Center**입니다(서드파티 앱 것도). 창 제목은
  아이템의 autosave 이름(`Item-0`, `MyBarHidden` …).
- 소유 앱은 각 앱의 `AXExtrasMenuBar` 자식 요소 위치를 창 위치와 맞춰서 알아냅니다.
- `NSStatusItem Preferred Position <이름>` 기본값 = 화면 오른쪽 끝에서 아이템 오른쪽 끝까지 거리.
- **창 제목은 화면 기록 권한이 있어야 보입니다.** 권한이 없으면 MyBar가 자기 구분선을 찾지
  못해 이동이 전부 실패하고, 덮개도 못 찍어 메뉴바가 펼쳐지는 모습이 그대로 보입니다.
  그래서 화면 기록은 "선택"이 아니라 **필수** 권한입니다.

- 상태 아이템 창을 찾는 기준(레이어 25, 높이 ≤ 50pt, 디스플레이 맨 위)은 macOS 26 실측값입니다.
  macOS 27(Golden Gate)에서는 이 기준에 맞는 창이 하나도 없어 아이템 목록이 비었습니다(원인: 27에서는
  아이템별 창이 없음 → macos27.md). 그래서 MyBar 자신의 아이콘 창(제목 `MyBarControl`)을 찾아 그 레벨·높이·위치를
  기준으로 삼습니다(`MenuBarScanner.statusWindowShape`).
- 앱 안에서 본 `NSStatusItem.button.window.windowNumber`는 창 서버 ID가 **아닙니다**
  (예: 4294967296). 이걸 `CGWindowID`로 바꾸면 크래시. 자기 창도 제목으로 찾아야 합니다.

## 여러 디스플레이

- 진짜 상태 아이템 창(같은 창 ID, autosave 제목)은 **활성 메뉴바가 있는 디스플레이**에만
  있습니다. 다른 디스플레이에는 번들 ID나 빈 제목의 복사본 창이 있습니다(반투명, 드래그 불가).
- 활성 메뉴바는 커서 이동으로는 안 바뀌고, 다른 디스플레이 메뉴바의 빈 곳을 **클릭**하면
  바뀝니다. MyBar는 `MyBarControl` 제목 창이 있는 디스플레이를 활성으로 봅니다.
- AX 좌표는 AX가 활성으로 보는 메뉴바 기준입니다. 디스플레이마다 오른쪽 끝 기준 거리로 변환
  (`DisplayMapping`).
- 외부 디스플레이가 활성일 때 화면 밖 아이템의 AX 위치가 엉터리(x≈85)로 나올 때가 있습니다.
  창 ID는 유지되므로 마지막으로 맞춘 소유자를 창 ID로 기억해 둡니다(`OwnerMemory`).

## 노치

- 노치 영역(내장 디스플레이 기준 790–1010pt)과 그 왼쪽의 상태 아이템은 그려지지 않고
  (`kCGWindowIsOnscreen` false) 집을 수 없습니다.
- **노치 오른쪽 약 20pt 안쪽에서 시작하는 아이템도 그려지지 않습니다**(1026에서 시작한 아이템은
  안 그려지고 1030은 그려짐). `MenuBarGeometry.notchClearance = 20`.
- 커서는 노치 뒤로 갈 수 있고, 드래그한 아이템을 노치 뒤·그려지지 않은 아이템 위에 **놓을 수는
  있습니다** → 슬라이딩의 근거.
- 아이템을 들어 올리면 그 **왼쪽** 아이템들이 들어 올린 폭만큼 오른쪽으로 당겨집니다.

## 이벤트 합성

- 이동은 HID 탭(`.cghidEventTap`)에 ⌘ 플래그를 단 마우스 다운 → 드래그들 → 업으로 합니다.
- **커서 없이 옮기기는 안 됩니다.** `postToPid`/`SLEventPostToPid` + 창 필드
  (`mouseEventWindowUnderMousePointer` 등) + `CGEventSetWindowLocation` 조합도 macOS 26에서는
  아이템이 움직이지 않았습니다. 세션 탭에 보내면 커서가 실제로 움직입니다. 그래서 커서는
  반드시 움직이고, MyBar는 그걸 숨기고 그림으로 대신 보여 줍니다.
- **클릭 카운트**: 합성 이벤트의 `mouseEventClickState` 기본값은 0입니다. 일부 앱(flow 등)은
  0이면 클릭을 무시합니다(눌린 표시만 남고 메뉴가 안 뜸). 다운/드래그/업 모두 1로 설정.
- **⌘가 눌린 채로 남음**: ⌘ 플래그를 단 마우스 이벤트를 HID 탭에 보내면 시스템이 ⌘ 키를
  누른 상태로 기억합니다(`CGEventSource.keyState(.hidSystemState, 0x37)` = true). 이후 사람의
  클릭이 전부 ⌘-클릭이 되어, 메뉴바 아이템 클릭이 "열기"가 아니라 "재배치 시작"이 됩니다
  (→ "가끔 ‹를 눌러도 안 열림"). 드래그 후 ⌘ 키-업 이벤트를 꼭 보냅니다.
- 드래그 속도(실측): 단계 5~10회 × 5ms, 놓기 전 대기가 짧으면(25ms) 구분선을 넘는 드롭이
  옆에 떨어지는 경우가 있어 60ms(`swift`). 같은 구역 안 슬라이딩은 25ms로 충분(`slide`).
  긴 거리는 한 단계 30pt 이하로 쪼갬. 받아들여진 드래그는 약 10ms 안에 창이 움직이므로
  정착 확인은 약 0.2초면 실패를 판단할 수 있음.
- **아주 짧은 드래그는 무시됩니다.** 옆 아이템을 바로 왼쪽에 떨어뜨리는 슬라이딩은 이동 거리가
  14pt 정도라 메뉴바가 재배치로 받아들이지 않습니다. 이동 거리가 30pt 미만이면 드롭 지점을
  지나쳤다가 돌아오는 경유점을 넣습니다(`EventDriver.minimumTravel`).
- 드래그 중 사람이 마우스를 움직이면 드래그가 깨집니다 → 드래그하는 동안만 이동 이벤트 보류.

## 저장된 위치로 구분선 옮기기 (드래그 없이)

- 각 앱 기본값의 `NSStatusItem Preferred Position <autosave 이름>`은 **현재 펼친 레이아웃에서**
  화면 오른쪽 끝 ~ 아이템 오른쪽 끝 거리이고, 시스템이 배치가 바뀔 때마다 갱신합니다(실측: 노치
  뒤 아이템까지 실제 프레임과 정확히 일치). 값이 클수록 왼쪽.
- MyBar는 자기 상태 아이템을 지우고(`removeStatusItem`) 새 위치 값을 저장한 뒤 다시 만들면
  그 위치에 놓을 수 있습니다(지울 때 현재 위치가 저장되므로 **지운 다음에** 값을 써야 함).
- 노치 화면 하나뿐이고 집을 수 있는 아이템이 없을 때(예: Always Hidden 아이템을 Hidden으로),
  구분선을 대상 아이템 바로 옆으로 옮겨 구역을 바꿉니다(`ItemMover.moveDivider`). 사이에 있던
  같은 구역 아이템도 함께 넘어가므로 끝나고 원래 구역으로 되돌립니다(`displaced`).
- 다른 디스플레이가 연결돼 있으면 예전에는 그 메뉴바로 전환해서 해결했습니다. 그래서 외부 모니터를
  쓰는 Mac에서는 잘 되고, 노트북 화면 하나뿐인 Mac에서는 실패했습니다. 디버그 빌드는
  `MYBAR_SINGLE_DISPLAY=1`로 단일 디스플레이 상황을 흉내 낼 수 있습니다.

## 커서 숨기기

- 백그라운드 앱은 `CGSSetConnectionProperty(conn, conn, "SetsCursorInBackground", true)` 후
  `CGDisplayHideCursor`로 숨길 수 있습니다.
- **사람이 마우스를 움직이면 시스템이 다시 보이게 합니다.** 커서 대역이 떠 있는 동안 120Hz로
  확인해 다시 숨깁니다(`Cursor.keepHidden`). 표시할 때는 숨긴 횟수만큼 보이고, 그래도 안
  보이면 추가로 보이게 합니다(커서가 사라진 채 남는 것이 최악).
- `CGWarpMouseCursorPosition`은 몇 ms 늦게 반영됩니다. 반영 전에 커서를 보이면 메뉴바 쪽에서
  한 번 번쩍입니다 → 원위치 도착을 확인한 뒤 보이기.
- 커서를 숨긴 직후 그림 창이 화면에 뜨기까지 수십 ms 비는 구간이 있음 → 그림을 먼저 띄우고
  20ms 뒤 숨김.

## 화면 캡처·오버레이 창

- 화면 밖 상태 아이템 창은 캡처되지 않습니다(SCK 오류). 노치 뒤도 마찬가지. 그래서 아이템
  그림은 잠깐 펼쳐서 찍는 "캡처 패스"로 얻고 디스크에 캐시합니다.
- 오버레이 창은 `animationBehavior = .none`이어야 합니다. 기본 애니메이션은 표시/숨김 때 창을
  살짝 확대해서 **메뉴바 전체가 왼쪽으로 흔들리는 것처럼** 보입니다.

## 권한(TCC)

- 손쉬운 사용, 화면 기록 둘 다 필수.
- 애드혹(`-`) 서명은 빌드마다 서명이 바뀌어 macOS가 **다른 앱으로 취급**합니다. 시스템 설정에서
  MyBar가 켜져 있어도 실제로는 적용 안 될 수 있음 → `tccutil reset Accessibility dev.gimbap.mybar`
  (그리고 `ScreenCapture`) 후 다시 허용. 인증서(Developer ID)로 서명하면 해결.
  macOS 27에서도 동일. 자세한 원리와 앱 안의 Reset 버튼 → releasing.md.
- DMG에서 바로 실행하거나 격리 속성이 남은 채 다른 곳에서 실행하면 App Translocation(임시 경로)
  사본이 되어 권한이 붙지 않습니다.
- 터미널에서 직접 실행한 바이너리는 터미널의 권한을 물려받습니다. 테스트가 잘 되다가
  `/Applications`에 설치하면 안 되는 경우는 대부분 이것.

## 기타

- 다른 앱의 메뉴가 열려 있을 때 메뉴바 클릭은 먼저 그 메뉴를 닫는 데 쓰입니다.
- 앱마다 열리는 UI가 다릅니다: 메뉴(레이어 101), 팝오버(1–24), 상태 레벨(25) 패널
  (PokeTokenBar), 일반 창(0). "열렸는지" 감지할 때 모두 고려해야 합니다.
